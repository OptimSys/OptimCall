OptimCall Event Notification Service

Download OpenAPI specification:

Overview

The Event Notification Service delivers real-time notifications about call activity to external applications such as CRM systems or helpdesks. It reports every relevant change in the state of a call throughout its lifecycle — from the moment a call starts, through the ringing and connection of individual parties, to the moment the call ends and its recording becomes available.

This specification documents the event payloads the service sends. Events fall into two groups:

  • Call events describe the call as a whole.
  • Call leg events describe an individual call leg — the connection between OptimCall and a single endpoint (a caller, a called party, a transfer target, or a participant monitoring the call). Each leg event also mirrors the call-level information available at the moment it occurs, so it reflects the state of the call as a whole in addition to the leg's own progress.

The events in each group, and the data they carry, are listed under Event payload structure below.

Event payload structure

Within each group, events are cumulative: every event includes all the information of the previous event in its sequence, plus new information specific to that stage. A later event is therefore always a superset of the earlier ones — no attributes present before are ever removed as the call progresses.

The aim is to let integrators treat event handling as stateless wherever possible: a consumer that only needs the final state of a sequence can therefore rely on the last (most detailed) event alone, without tracking or merging the earlier ones.

The one exception is tags: unlike other call details, tags can be added or removed while the call is in progress, so this list can shrink as well as grow from one event to the next.

All durations are measured up to the moment the event occurred. A duration of a call phase reported in an earlier event may therefore be partial and will grow in later events — for example, the total duration or the ringing duration.

Call events

Event What it represents What's included
callStarted A new call has begun Common metadata + basic details about the call as it starts (e.g. who is calling, what number is being called) + the call durations (all 0)
callConnected The call has been answered Everything from callStarted, plus details specific to the moment the conversation starts (e.g. who answered)
callDisconnected The call has ended Everything from the previous event, plus details about how and when the call ended
callRecordingReady A recording of the call is available Everything from callDisconnected, plus details needed to access the recording

callConnected is sent only if the call is answered. If no one answers, it is skipped and the sequence goes straight from callStarted to callDisconnected.

Call leg events

A leg event carries every call-level attribute already available at the moment it occurs and then adds its own leg-specific progression.

Event What it represents What's included
legRinging The leg starts ringing Basic call details + basic leg details + the leg durations (all 0)
legConnected The leg has answered Everything from legRinging, plus details about the answering party
legDisconnected The leg has ended Everything from the previous event, plus which party ended the leg

legConnected is sent only if the leg is answered. A leg that rings but is never answered goes straight from legRinging to legDisconnected.

Event delivery

The service can deliver the same events in one of two ways, selected in the service configuration:

  • Webhook mode — OptimCall sends each event to a preconfigured HTTPS endpoint as an HTTP POST request with a JSON body.
  • WebSocket mode — the external application opens a persistent WebSocket connection to OptimCall and receives events over that connection.

Both modes deliver identical event payloads; they differ only in how the connection is established and maintained.

Authentication

  • Webhook mode — if a secret is configured, OptimCall includes the X-OptimCall-Key header with that value in every request. The receiving endpoint should use it to verify that the request originates from OptimCall.

  • WebSocket mode — if a security token is configured, the client must connect with the Authorization: Bearer <token> header. If this is not possible (e.g. web browser limitations), the client can alternatively authenticate by sending the

        {
        "name":"authenticate",
        "token":"abc",
        "correlationId": "a1b2c3d4"
    }

    message.

    Regardless of the way the client authenticates, the server sends back the following response:

        {
        "name":"authenticateResult",
        "status":"success",
        "correlationId": "a1b2c3d4"
    }

    In case of an error, the status will be "error".

Delivery retries

If a webhook request fails, OptimCall retries it up to a configurable maximum number of retries, waiting a configurable retry interval (in seconds) between attempts.

Event filtering

Delivery can be narrowed with one or more filters, configured in the service's user interface. An event is delivered if it matches any configured filter (filters are combined with OR), and each event is delivered only once even when it matches several filters.

A filter can restrict delivery by:

  • Which events are sent — any subset of the call events and call leg events listed above.
  • Call type — external inbound, external outbound, and/or internal calls.
  • Leg type — caller, callee, transferee, and/or monitoring (applies to call leg events).
  • Specific numbers, further narrowing the calls selected above:
    • external inbound calls — only calls to the selected public numbers;
    • external outbound calls — only calls using the selected outgoing numbers;
    • external outbound and internal calls — only calls dialed from the selected extensions;
    • internal calls — only calls to the selected destination extensions;
    • callee legs of external inbound and internal calls — only legs to the selected destination numbers.

Call Events

Events describing the lifecycle of the call as a whole.

Call Started Webhook

Sent when a call is initiated. At this point no call legs have been created yet.

This is always the first event in a call’s lifecycle.

Request Body schema: application/json
name
string

Fixed value callStarted.

eventTime
string <date-time>

Time this specific event occurred.

callId
string

Unique identifier of the call. All events for the same call share this value.

callType
string
Enum: "externalInbound" "externalOutbound" "internal"

Type of the call:

  • externalInbound — an incoming call from an external number to a public number configured in OptimCall.
  • externalOutbound — an outgoing call placed from an extension to an external number.
  • internal — a call between two extensions.
startTime
string <date-time>

Specifies the date and time when the call was started. For inbound calls, it is when the call entered the system. For outbound and internal calls, this is when the caller placed the call.

startedByClickToCall
boolean

Indicates whether the call was initiated via click-to-call. true when the call was initiated via click-to-call, false when the number was dialed manually.

The attribute is present only for external outbound and internal calls.

callerNumber
string

Caller’s phone number. If it is a valid external phone number, it is in E.164 format.

callerName
string

Display name of the calling party.

This attribute is present only when a display name is known for the caller’s number.

calledNumber
string

Called phone number. If it is a valid public or external phone number, it is in E.164 format.

calledName
string

Display name of the called party.

This attribute is present only when a display name is known for the called number.

outgoingNumber
string

Phone number displayed on the recipient’s phone, indicating who is calling (caller ID). If it is a valid public phone number, it is in E.164 format.

This attribute is present only for external outbound calls.

outgoingNumberName
string

Display name associated with the outgoing number.

This attribute is present only for external outbound calls where a display name is available for the outgoing number.

tags
Array of strings

Tags currently assigned to the call, reflecting the tags in effect at the moment of this event.

Tags are not fixed for the lifetime of the call: they can be added or removed while the call is in progress, for example by a routing scenario. Consequently, this list can differ from one event to the next for the same call — an event may include a tag that a later event no longer has, or one that an earlier event did not yet have.

totalLength
integer

Total call duration, in seconds, measured up to the moment of this event. It is a running total that grows as the call progresses. It is final only once the call ends (callDisconnected / callRecordingReady).

Note that the duration of the Setup phase is excluded, as are post-call interactions within the Conversation phase — both are considered outside the standard call duration. Therefore, the total call duration is not a simple sum of the call phase durations.

The attribute is present in every event, with a value of 0 in callStarted, where no time has yet been counted.

setupLength
integer

Duration of the Setup phase, in seconds, measured up to the moment of this event. The Setup phase applies only to click-to-call calls: it is the time OptimCall spends ringing the caller’s own devices until the caller answers or the attempt times out.

Because OptimCall may ring several caller’s devices with delays between them, the value can be partial in an earlier event and grow in a later one while the phase is still in progress.

The attribute is present in every event, with a value of 0 for calls not initiated via click-to-call and in callStarted, which precedes the Setup phase.

welcomeLength
integer

Duration of the Welcome phase, in seconds. The Welcome phase occurs only in external inbound and internal calls: it is the time spent on initial audio playback and IVR interaction with the caller, and other actions before any attempt to connect the caller with recipients begins.

The attribute is present in every event. Because no event is ever delivered while the Welcome phase is in progress, the value is never a partial measurement: in callStarted it is still 0, as that event precedes the Welcome phase, and in every later event it is the final Welcome phase duration — 0 for external outbound calls and for calls that had no Welcome phase.

ringingLength
integer

Duration of the Ringing phase, in seconds, measured up to the moment of this event. It is the time from the start of call routing to recipients until the call is answered or disconnected.

While the call is in the ringing phase, multiple events can occur — for example, several legRinging events as different legs start ringing. Because of this, the value reported in an earlier event within this phase may be partial and can increase in a later event. It becomes final once the call connects or is disconnected.

The attribute is present in every event, with a value of 0 for calls that had no Ringing phase and in callStarted, which precedes it.

conversationLength
integer

Duration of the Conversation phase, in seconds, measured up to the moment of this event. It covers the time since the call was answered, including periods when the caller is placed on hold or transferred, as well as possible post-call interactions.

Further events can occur while the call is still in conversation — for example, a transfer produces new leg events. In those events the value is partial and can grow in a later event. It is final only in the call-end events, callDisconnected and callRecordingReady.

The attribute is present in every event, with a value of 0 in callStarted and callConnected and for calls that are never answered.

callOutcome
string
Enum: "notAnswered" "answered" "voicemail" "blocked" "setupFailed" "failed"

Final outcome of the call, indicating how it ended. Possible values:

  • notAnswered — No recipient answered the call.
  • answered — A recipient answered the call.
  • voicemail — The call was routed to voicemail. Applies only to external inbound and internal calls.
  • blocked — The call was blocked because the caller’s number was on a blocklist. Applies only to external inbound and internal calls.
  • setupFailed — During the click-to-call setup phase, the caller either rejected the call or the dial attempt to the caller’s devices timed out.
  • failed — The call failed due to an error.

When no recipient answered the call, although the value is always notAnswered, the name commonly used by people to describe it varies by call type:

  • An external inbound call that is not answered is usually called missed.
  • An external outbound call that is rejected by the remote party is usually referred to as rejected.
  • An external outbound call that the caller abandons and hangs up is typically called cancelled.
disconnectedBy
string
Enum: "caller" "callee" "system"

Indicates which party ended the call:

  • caller — the initiating participant ended the call.
  • callee — the receiving participant ended the call.
  • system — OptimCall ended the call, either automatically, through a user interface action or via an API request from a third-party application.

Call Recording Ready Webhook

Sent after the call has ended and its recording files have been processed and are ready for download.

Carries all fields of callDisconnected plus recording-specific fields. Because the recording is processed after the call ends, this event may arrive with a short delay after callDisconnected.

integer

Duration of the Ringing phase, in seconds, measured up to the moment of this event. It is the time from the start of call routing to recipients until the call is answered or disconnected.

While the call is in the ringing phase, multiple events can occur — for example, several legRinging events as different legs start ringing. Because of this, the value reported in an earlier event within this phase may be partial and can increase in a later event. It becomes final once the call connects or is disconnected.

conversationLength
integer

Duration of the Conversation phase, in seconds, measured up to the moment of this event. It covers the time since the call was answered, including periods when the caller is placed on hold or transferred, as well as possible post-call interactions.

Further events can occur while the call is still in conversation — for example, a transfer produces new leg events. In those events the value is partial and can grow in a later event. It is final only in the call-end events, callDisconnected and callRecordingReady.

string

Final outcome of the call, indicating how it ended. Possible values:

  • answered — A recipient answered the call.
  • voicemail — The call was routed to voicemail. Applies only to external inbound and internal calls.
  • blocked — The call was blocked because the caller’s number was on a blocklist. Applies only to external inbound and internal calls.

  • An external outbound call that is rejected by the remote party is usually referred to as rejected.

Leg Ringing Webhook

Sent when a call leg starts ringing on its endpoint (an extension device or a device identified by an external number).

If an inbound or internal call is routed to multiple recipients, a separate legRinging event is sent for each endpoint as it begins ringing. In addition, an extension can have several endpoint devices, and each such device is dialed as a separate leg and produces its own leg events.

Duration of the Ringing phase, in seconds, measured up to the moment of this event. It is the time from the start of call routing to recipients until the call is answered or disconnected.

While the call is in the ringing phase, multiple events can occur — for example, several legRinging events as different legs start ringing. Because of this, the value reported in an earlier event within this phase may be partial and can increase in a later event. It becomes final once the call connects or is disconnected.

The attribute is present in every event, with a value of 0 for calls that had no Ringing phase and in callStarted, which precedes it.

conversationLength
integer

Duration of the Conversation phase, in seconds, measured up to the moment of this event. It covers the time since the call was answered, including periods when the caller is placed on hold or transferred, as well as possible post-call interactions.

Further events can occur while the call is still in conversation — for example, a transfer produces new leg events. In those events the value is partial and can grow in a later event. It is final only in the call-end events, callDisconnected and callRecordingReady.

The attribute is present in every event, with a value of 0 in callStarted and callConnected and for calls that are never answered.

answeredByNumber
string

Extension number or external number that answered the call. If it is a valid external phone number, it is in E.164 format.

This attribute is present only if somebody answered the call.

answeredByName
string

Display name of the answering party.

This attribute is present only when the call was answered and a display name is known for the answering party.

legId
string

Unique identifier of the call leg. All events for the same call leg share this value.

legType
string
Enum: "caller" "callee" "transferee" "monitoring"

Role of the call leg within the call structure:

  • caller — the leg between the originating party and OptimCall. Each call has exactly one caller leg, with one exception: during click-to-call, when OptimCall dials the initiating party’s devices, multiple caller legs can exist simultaneously if several devices are dialed.
  • callee — a leg between OptimCall and a call recipient. A call may ring several recipients, so multiple callee legs can exist.
  • transferee — a leg between OptimCall and a participant to whom the call is transferred. A call may be transferred repeatedly, producing multiple transferee legs.
  • monitoring — a leg between OptimCall and a participant who silently monitors the call (listening without being heard).
legNumber
string

Phone number of the party on this leg, either an extension number or an external number. If it is a valid external phone number, it is in E.164 format.

legName
string

Display name associated with the number of the party on this leg, if known.

This attribute is present only when a display name is known for the leg number.

legDeviceId
string

ID of the endpoint device on this leg, used to distinguish between multiple devices associated with the same extension.

This attribute is present only when the party on this leg is an extension (not an external number).

legDeviceName
string

Name of the endpoint device on this leg, as configured in the system.

This attribute is present only when the party on this leg is an extension (not an external number) and the endpoint device on this leg has a configured name.

legDirection
string
Enum: "inbound" "outbound"

Direction of the call leg relative to OptimCall:

  • inbound — the remote endpoint initiated the leg to OptimCall.
  • outbound — OptimCall initiated the leg to the remote endpoint.
legTotalLength
integer

Total duration of this leg, in seconds, measured up to the moment of this event. It covers the time from the start of dialing the endpoint device on this leg (when the leg is created) up to the moment of this event, and equals legRingingLength + legConnectedLength.

The attribute is present in every leg event. It is 0 in legRinging, where the leg has only just been created; partial in legConnected, where the leg is still in conversation; and final in legDisconnected.

legRingingLength
integer

Duration for which this leg was ringing, in seconds. It measures the time from the start of dialing the endpoint device on this leg (when the leg is created) until the device answers or the leg is disconnected.

The attribute is present in every leg event. Because no event is delivered while the leg is ringing, the value is never a partial measurement: it is 0 in legRinging, which is sent as the leg starts ringing, and final in legConnected and legDisconnected, by which time the leg has stopped ringing.

legConnectedLength
integer

Duration for which this leg was connected — that is, in conversation — in seconds. It measures the time from when the endpoint device on this leg answered until the leg is disconnected.

The attribute is present in every leg event, with a value of 0 in legRinging and legConnected. It is final in legDisconnected, and remains 0 there if the leg was never connected.

legDisconnectedBy
string
Enum: "endpoint" "system"

Indicates which party caused the call leg to disconnect:

  • endpoint — the endpoint disconnected itself (e.g. the participant hung up or rejected the call).
  • system — OptimCall disconnected the leg (e.g. after another leg answered, or because the call was transferred or ended).
